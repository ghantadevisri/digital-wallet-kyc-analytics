\# Data Dictionary (v1)



Project: Digital Wallet KYC Funnel \& Retention Analytics

Data type: \*\*synthetic (simulated) data\*\*, generated by `scripts/generate\_data.py` (seed = 42).

Simulated "today" (snapshot date): \*\*2026-09-30\*\*. Sign-ups run from 2025-01-01 to 2026-06-30.



> Raw files are intentionally messy. The "Standard values" columns below describe what each field

> should look like \*\*after\*\* cleaning in Week 2.



\---



\## 1. users

One row per registered user (after cleaning). Grain: `user\_id`.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| user\_id | text | Unique ID of a registered user. Primary key. | Format `U000001`. Must be unique after de-duplication. |

| signup\_date | date | Day the user created a wallet account. Start of the funnel. | `YYYY-MM-DD` |

| city | text | City the user registered from. | Mumbai, Delhi, Bengaluru, Hyderabad, Chennai, Pune, Kolkata, Ahmedabad, Jaipur, Lucknow, Indore. Blank in raw data; "Unknown" in clean data. |

| device\_type | text | Platform used to sign up. | Android, iOS, Web |

| acquisition\_channel | text | Marketing source that brought the user in. | Organic, Paid Social, Google Ads, Referral, Influencer, Offline Agent |

| age\_band | text | Age group of the user. | 18-24, 25-34, 35-44, 45-54, 55+. Blank in raw data; "Unknown" in clean data. |



\## 2. kyc\_events

One row per KYC \*\*attempt\*\*. A user can have 0, 1 or 2 rows (a rejected user may retry). Grain: user + attempt.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| user\_id | text | User who submitted KYC. Foreign key to `users`. | No row = user never started KYC. |

| kyc\_started\_at | timestamp | When the user began this KYC attempt. | `YYYY-MM-DD HH:MM:SS`. Must not be before signup. |

| kyc\_completed\_at | timestamp | When a decision (approve/reject) was recorded. | Blank when status is PENDING. Must not be earlier than `kyc\_started\_at` or signup. |

| kyc\_status | text | Outcome of the attempt. | APPROVED, REJECTED, PENDING (started but not decided / abandoned) |

| rejection\_reason | text | Why the attempt was rejected. | Only filled when status = REJECTED: Blurry document, Name mismatch, Selfie mismatch, Expired document, Invalid document number, Address proof missing |



\## 3. transactions

One row per payment attempt by a user. Grain: `transaction\_id`.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| transaction\_id | text | Unique ID of a transaction. Primary key. | Format `T00000001`. Must be unique after de-duplication. |

## Changes after Week 2 cleaning (files in data/clean/)
- users_clean.csv: 20,000 rows, one per user_id. Blank city and age_band are filled with "Unknown". All categories use the standard values listed above.
- kyc_events_clean.csv: 16,792 rows. New column `has_date_issue` (1 = completion earlier than signup or start, 0 = fine). Exclude flagged rows when calculating time to approval.
- transactions_clean.csv: 101,291 rows. Duplicate transaction_ids and TEST_USER accounts removed. New column `has_amount_issue` (1 = amount is zero or negative). Exclude flagged rows when counting successful transactions.
- app_events and date_dimension are used as generated. Duplicate events and blank session_ids in app_events are handled in SQL (Week 3).
