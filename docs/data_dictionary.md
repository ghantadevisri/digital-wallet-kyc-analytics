\# Data Dictionary (v1)



Project: Digital Wallet KYC Funnel \& Retention Analytics

Data type: \*\*synthetic (simulated) data\*\*, generated by `scripts/generate\_data.py` (seed = 42).

Simulated "today" (snapshot date): \*\*2026-09-30\*\*. Sign-ups run from 2025-01-01 to 2026-06-30.



> Raw files are intentionally messy. The "Standard values" columns below describe what each field

> should look like \*\*after\*\* cleaning in Week 2.



\---



\## 1. users

One row per registered user (after cleaning). Grain: `user\_id`.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| user\_id | text | Unique ID of a registered user. Primary key. | Format `U000001`. Must be unique after de-duplication. |

| signup\_date | date | Day the user created a wallet account. Start of the funnel. | `YYYY-MM-DD` |

| city | text | City the user registered from. | Mumbai, Delhi, Bengaluru, Hyderabad, Chennai, Pune, Kolkata, Ahmedabad, Jaipur, Lucknow, Indore. Blank = unknown. |

| device\_type | text | Platform used to sign up. | Android, iOS, Web |

| acquisition\_channel | text | Marketing source that brought the user in. | Organic, Paid Social, Google Ads, Referral, Influencer, Offline Agent |

| age\_band | text | Age group of the user. | 18-24, 25-34, 35-44, 45-54, 55+. Blank = unknown. |



\## 2. kyc\_events

One row per KYC \*\*attempt\*\*. A user can have 0, 1 or 2 rows (a rejected user may retry). Grain: user + attempt.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| user\_id | text | User who submitted KYC. Foreign key to `users`. | No row = user never started KYC. |

| kyc\_started\_at | timestamp | When the user began this KYC attempt. | `YYYY-MM-DD HH:MM:SS`. Must not be before signup. |

| kyc\_completed\_at | timestamp | When a decision (approve/reject) was recorded. | Blank when status is PENDING. Must not be earlier than `kyc\_started\_at` or signup. |

| kyc\_status | text | Outcome of the attempt. | APPROVED, REJECTED, PENDING (started but not decided / abandoned) |

| rejection\_reason | text | Why the attempt was rejected. | Only filled when status = REJECTED: Blurry document, Name mismatch, Selfie mismatch, Expired document, Invalid document number, Address proof missing |



\## 3. transactions

One row per payment attempt by a user. Grain: `transaction\_id`.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| transaction\_id | text | Unique ID of a transaction. Primary key. | Format `T00000001`. Must be unique after de-duplication. |

| user\_id | text | User who made the payment. Foreign key to `users`. | Internal test accounts (`TEST\_USER\_xx`) are not real customers. |

| transaction\_date | timestamp | When the payment was attempted. | `YYYY-MM-DD HH:MM:SS` (contains a time part despite the name). |

| amount | number | Transaction value in INR. | Should be greater than 0. |

| status | text | Result of the payment. | SUCCESS, FAILED, REVERSED. Only SUCCESS counts as a "successful transaction". |

| payment\_type | text | Kind of payment. | UPI Transfer, Merchant Payment, Bill Payment, Mobile Recharge, Wallet Top-up |



\## 4. app\_events

One row per in-app event. Used for activity and recency analysis. Grain: one event.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| user\_id | text | User who triggered the event. Foreign key to `users`. | |

| event\_time | timestamp | When the event happened. | `YYYY-MM-DD HH:MM:SS` |

| event\_name | text | What the user did. | signup\_complete, kyc\_started, kyc\_approved, kyc\_rejected, payment\_success, payment\_failed, app\_open |

| session\_id | text | Groups events from one user on one day into a session. | Format `S00000001`. Occasionally blank (tracking glitch). |



\## 5. date\_dimension

One row per calendar day (2025-01-01 to 2026-12-31). Grain: `date`.



| Field | Type | Business meaning | Standard values / notes |

|---|---|---|---|

| date | date | Calendar day. Primary key. | `YYYY-MM-DD` |

| year | integer | Calendar year. | |

| quarter | integer | Calendar quarter. | 1-4 |

| month | integer | Month number. | 1-12 |

| month\_name | text | Month name. | January ... December |

| week | integer | ISO week number. | Use together with `week\_start\_date` to avoid year-boundary confusion. |

| week\_start\_date | date | Monday of that week. | Safe key for weekly grouping. |

| day\_of\_week | text | Day name. | Monday ... Sunday |

| is\_weekend | integer | 1 if Saturday or Sunday. | 0 / 1 |



\---



\## Key definitions used throughout the project

\- \*\*Registered user:\*\* a unique `user\_id` in `users`.

\- \*\*KYC started:\*\* user has at least one row in `kyc\_events`.

\- \*\*KYC approved:\*\* user has at least one `kyc\_events` row with status APPROVED.

\- \*\*Activated user / first transaction:\*\* user has at least one transaction with status SUCCESS (test accounts excluded).

\- \*\*Repeat transaction:\*\* a second SUCCESS transaction within 30 days of the first.
